I wanted to keep my personal tech notes in a form that is easy to find later, so I set up a blog with a static site generator. **What got me started** was reading [Nyosegawa's "How I built this blog with Lume"](https://nyosegawa.com/posts/hello-lume/). The flow — initializing with Deno, using the Simple Blog theme, deploying to GitHub Pages — was easy to follow sentence by sentence, and it felt like something I could try from the same starting point. I use **Deno** as the runtime, **Lume** to generate the site, and the **Simple Blog** theme as the visual foundation. This post walks through the folder layout, deployment, and how I fixed the parts that didn't quite line up, so it can serve as a hint for reproducing the setup.

## Why I chose Lume

Node.js-based tools were also candidates, but I liked how Lume handles dependencies and lets me write the config file in TypeScript, so I leaned toward it. Adding plugins and filters in `_config.ts` is straightforward, and being able to build just by dropping Markdown and templates (`.vto`) into `src/` made it a good fit for starting small.

## Skeleton of the repository

The articles themselves are Markdown files in `src/posts/`. The front matter holds the title, date, and tags, and the build outputs HTML into `_site/`. I override the theme's layouts under `src/_includes/`, and the overall style leans slightly toward Material Design 3 colors via `src/zenn.css`. The top page doesn't list article bodies; instead you jump to each post from a card, and the card images are PNGs generated by a script described below.

In the config I enable the **`base_path` plugin**. A GitHub Pages project site has a URL like `https://username.github.io/repository-name/`, so the **repository name is part of the path**. That means links starting with just a leading slash would unintentionally point to the root. Lume's `base_path` corrects internal links in the HTML, and for OG images and thumbnails I build the paths from the site's `location` (the `SITE_URL` environment variable) using the **`postOgImage`** and **`thumbUrl`** filters in `_config.ts`.

## OGP and thumbnails

The per-article OGP image and the list thumbnail are generated by `scripts/generate-og.ts`. In the build steps I run `deno task og` first, then the Lume build. Because one of the CDNs could become flaky on CI, font loading **prefers jsDelivr and falls back to unpkg**, and if needed reads a **`.woff` placed in `scripts/fonts/`**, so the same command tends to pass either way.

## Things I added around the article page

At the top of the article body in the post layout, I placed a small line that reads **"This post was written together with an AI agent."** The style is set in `zenn.css` to be lighter than the body text. Near the header I also added a share row — **X, Facebook, LINE, Hatena, and copy URL** — as a partial, and added an **`encodeURIComponent`** filter in `_config.ts` to assemble the share query strings.

## RSS and JSON Feed links

Only the in-article links inside the feed body would temporarily resolve to the wrong absolute URL. When Lume's feed plugin rewrites `/posts/...` in the body, the way the URL resolves can produce a **host-root `/posts/`**, dropping the repository-name path. The HTML is fixed by `base_path`, but the feed pages are **only added to `site.pages` during `beforeSave`**, so I added a step in `_config.ts` that, at that same moment, replaces just the body of **`feed.xml` and `feed.json`** with the correct prefix.

## GitHub Actions and Pages

Pushing to `main` builds with GitHub Actions and publishes the artifact to GitHub Pages. The **`SITE_URL`** environment variable is assembled in the workflow from `github.repository_owner` and `github.event.repository.name`, so it keeps up even if the repository name changes. On the first run, unless you set **the repository's Settings → Pages Source to GitHub Actions**, `deploy-pages` can return a 404. I noted that step briefly in the README too.

I also aligned the repository name to **`yasuna-tech`**, and updated the README, the GitHub link in my profile, and the default `SITE_URL` in `generate-og.ts` (when unset) so they all match the public URL.

## Editing with Cursor's Composer 2 Fast

I built and tweaked this blog in the **Cursor** editor. When using the agent I often pick **Composer 2 Fast** — responses are light and the wait is short — so appending to config files, making changes across several files, and even checking the build in the terminal kept the conversation tempo from breaking. It was **incredibly comfortable**, and I found it well suited to this kind of "try small and build up" work.

## Wrap-up

On a foundation of Deno, Lume, and Simple Blog, I wired together articles, listings, search, and feeds, and gradually touched up the GitHub Pages paths and the CI flakiness. I'd be happy if you read this not as a comparison table but as **one implementation example** for anyone setting up a personal blog the same way. For the finer config details, the surest reference is the repository's `_config.ts` and README.
